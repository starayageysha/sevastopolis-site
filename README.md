# СЕВАСТОПОЛИС — этап 1

## Публикация через GitHub Pages

В репозитории уже настроен workflow: каждый push в `main` публикует содержимое корня сайта. Для первого запуска:

1. В GitHub откройте **Settings → Pages** и выберите **GitHub Actions** в разделе Build and deployment.
2. После публикации добавьте `sevastopolis.ru` в поле **Custom domain** и сохраните.
3. В DNS-панели регистратора создайте четыре записи `A`: для имени `@` укажите `185.199.108.153`, `185.199.109.153`, `185.199.110.153` и `185.199.111.153`. Удалите конфликтующие записи `A`/`AAAA` для `@`, если они ведут в другое место.
4. Дождитесь обновления DNS, затем включите **Enforce HTTPS** в Settings → Pages.

GitHub Pages на бесплатном тарифе требует публичный репозиторий. DNS и сертификат настраиваются в аккаунтах GitHub и регистратора домена; из этого проекта ими управлять нельзя.

## Возможности и ограничения прототипа

Это статический сайт. Раздел регистрации работает в демо-режиме и хранит данные только в локальном хранилище браузера посетителя; общего аккаунта на сервере нет. Перед настоящей регистрацией нужны сервер API, безопасное хранение паролей и готовая политика конфиденциальности. Игровая сборка тоже не приложена: раздел «Играть» станет доступен после её подключения.
Запуск: откройте `index.html` в браузере, либо в папке выполните `python3 -m http.server 8000` и откройте http://localhost:8000
Хостинг (sevastopolis.ru): загрузите всю папку в корень сайта.
## Свои картинки
Положите файлы в `assets/img/` под теми же именами (intro, world, family, cat, wide, poster — .webp; logo.png). Чтобы добавить новый раздел или картинку, правьте массив `S` в `js/main.js`.
## Игра
Раздел «Играть» (`#play`) — место для подключения сборки (iframe или ссылка). Игровая сборка не затронута.
## Нужна графика
Логотип без фона отдельным PNG для шапки, иконки разделов, кнопки, изображения персонажей, NPC, транспорта, музыкальный файл.

## Как наполнять
Все разделы, тексты и картинки — в `js/content.js` (поля t, lead, bg, cards, gallery). Новый раздел: добавьте объект в `pages` и ключ в `main`. Игра: впишите адрес в `GAME_URL` — раздел «Играть» покажет её во встроенном окне.

## Музыка
Файлы в `assets/audio/`. Список треков — массив `TR` в `js/main.js`. Музыка включается кнопкой ♪; на каждой странице играет случайный другой трек, при переходе предыдущий плавно затухает.

## Изображения и композиция (v3)
- Фоны БЕЗ вшитых надписей лежат в `assets/img/` (poster, tall, intro, family, cat, wide, world). Исходные версии с надписями — в `assets/img/originals/`.
- Заставка и главная: небо (градиент) + сцена снизу. Для телефона (вертикальный экран) и компьютера (горизонтальный) картинки выбираются отдельно через `<picture>` в `index.html` и `js/main.js`.
- Логотип — `assets/img/logo.png` (отдельный слой, меняется независимо от фона).

## Регистрация (v6)
Файл `js/auth.js`. Сейчас работает ДЕМО-режим: аккаунты хранятся только в браузере посетителя (для проверки интерфейса).
Для настоящей регистрации нужен сервер: впишите адрес в `API_URL` (`js/content.js`). Сайт ждёт такие запросы (JSON, cookie-сессия):
- `POST /api/register` {email,password,nickname,avatar,consent} -> {user}
- `POST /api/login` {email,password} -> {user}; `POST /api/logout`
- `GET /api/me` -> {user}; `PATCH /api/player` {nickname,avatar} -> {user}
Ответ {user}: {email, player:{nickname,avatar}}; ошибка: статус 4xx и {error:"текст по-русски"}.
Сервер должен хранить пароль только в виде хеша (bcrypt/argon2), работать по HTTPS и проверять данные сам.
Текст политики конфиденциальности — раздел `#privacy` в `js/content.js` (нужно подготовить до запуска).
